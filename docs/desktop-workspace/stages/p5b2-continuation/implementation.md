# P5B-2 implementation guide

Owner authorized on 2026-09-27 after the P5B-1 result review. Retain the dirty working tree; no commit, staging, publication, image replacement or App enablement. Baseline: all P5B-1 production hashes match; existing history/admission/Stop tests pass in the installed Linux toolchain container. Docker Desktop was started for authorized local verification.

Reach: preparation owns typed review facts; engine owns read-only eligibility, content verification, reviewed admission and scheduler construction; exec owns a read-only proof that a recorded Docker submission no longer exists; the public prepared boundary binds the actual runtime. Existing scheduler gains a bounded staged-input check only for prepared continuation. App, CLI transport, capability negotiation and UI are no-ops in this increment. No generated contract changes yet: TypeScript schemas belong to later integration.

Slices: (1) immutable review of an exact schema-2 stopped Run, complete sealed-plan comparison, exact installed identities, input/output content and absent backend submissions; prove read-only success and fail-closed states. (2) under the existing ownership lock, recompute review, compare digest, persist one receipt and attempt plan before scheduling; prove exact replay, conflict/stale refusal, history/Stop isolation, staged-input drift, cancellation and publication-failure recovery. (3) public prepared functions bind engine/daemon and preserve existing Start behavior; run affected Linux/race and native checks. Stop at the engine result checkpoint, before App integration.

Units: `continuation_review.go` defines engine eligibility; owns exact facts and their digest; hides source/document internals from the review; uses preparation/exec and is used by review/admission. `continuation_admission.go` defines admitted continuation; owns lock/receipt/scheduler transfer; never imports App; uses review and existing scheduler. Preparation review values define bounded visible decisions, hide executable code, and are consumed by engine/public callers. `VerifySubmissionAbsent` defines settled backend identity, owns read-only daemon queries, never copies logs or removes containers, and is used by engine review. Public prepared functions define trusted host entry points and validate actual runtime before engine calls. No interfaces, classes, generic recovery framework or new journal.

Semantics: successful prefix tasks keep their attempts; incomplete tasks require recorded cancellation and receive attempt + 1; never-started tasks keep their unexecuted attempt. Failed, blocked, unknown or published-unfinalized tasks are refused. Missing/changed completed results never become silent reruns. Exact receipt replay returns without rescheduling, including after an uncertain acknowledgement or later completion. Review does not reconcile ownership or mutate task evidence. Existing prepared Resume guard remains.
