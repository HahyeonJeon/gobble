## Future measures and guardrails

Owner: App maintainer; consumer: Project owner/research workflow reviewer. Review a bounded set of opted-in acceptance sessions at the first P5 delivery, without collecting raw messages/data for analytics.

- Can a person identify the exact earlier attempt and Current base? Intended: correct reference. Harmful proxy: more attachments mistaken for more accuracy. Guardrail: zero silent retargeting; a wrong target reopens the design.
- Can a person distinguish adoption from Start and fresh Run from Resume? Intended: informed action. Harmful proxy: fewer clicks mistaken for better consent. Guardrail: no unanticipated execution; any mistaken execution expectation reopens copy/action placement.
- Can a person recover from unavailable evidence or changed Current? Intended: preserve context while requesting a new check. Harmful proxy: successful task count hides abandoned work. Guardrail: record failed paths and unavailable sources, not only completions.

At delivery, explicitly decide improvement/no-change and the maintenance owner from observed evidence. No continuous telemetry, notification or automation is authorized by this proposal.
